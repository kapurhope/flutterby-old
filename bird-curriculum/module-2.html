The Hungry Bird Robot

Students build a simple rule from beak-race scores, test it like an AI, then see what happens when the robot only gets incomplete data.

Computer optional 35–40 min Uses Module 1 data

Teacher training PDF Student rule card

Learning goal

Students can explain: A robot only knows the examples we give it. If the examples are incomplete, its rule can be wrong.

  • Write one fair rule from beak scores to send a hungry bird to a wet place or a forest.
  • Test the rule on a new “mystery bird” (robot follows the card only).
  • See how an unfair sample (spoon-only data) breaks the rule.
  • Answer: “Did the robot fail, or did we give it a bad / incomplete lesson?”

Learning points for teachers

  1. AI = a rule from examples — not magic.
  2. Test on something new — a rule isn’t real until it faces a mystery bird.
  3. Bias can mean incomplete data — only showing spoon results skews the lesson.
  4. Humans are responsible for the lesson the AI got.

Do not invent a “silly rule” just to tear it down. If a student offers a looks/color shortcut, you may test that later as an optional add-on.

Materials

  • Module 1 class scores on the board (spoon, tweezers, fork) or sample table below
  • Rule card (one per pair)
  • Index card for the “Robot” volunteer
  • Optional: mystery bird cards

Lesson flow

“Yesterday we were birds hunting for food. Today we build a tiny AI that decides where a hungry bird should go for the most food — wet place or forest.”

1) Hungry-bird question + fair rule (8–10 min)

Ask: “If you were a robot, and you could only look at these numbers, what rule would you use to decide where the hungry bird should go for the most food — a wet place or a forest?”

Land one short fair rule, e.g. If Water food ≥ 10 → Wet place. Otherwise → Forest. Write it on the Robot’s card.

2) Test on a mystery bird (8 min)

Robot may only read the card. Example: Water food 16, Worms 3 → Wet place. Class votes first; then Robot answers.

Point: the robot didn’t “know birds” — it matched numbers to a rule.

3) Unfair sample — spoon-only data (10–12 min)

Cover tweezers and fork. Ask what rule the robot would learn from spoon data alone (often “always wet”). Uncover other beaks; test tweezers with the spoon-only rule — it fails.

Name it: incomplete / unfair sample — we gave the robot a skewed lesson.

4) Close (3–5 min)

Ask: “Did the robot fail, or did we give it a bad / incomplete lesson?”

Exit ticket: “Today the AI messed up because ___.”

Assessment

Completed rule card + exit ticket. Look-fors: uses scores in the fair rule; can explain spoon-only failure as our incomplete lesson, not a “mean robot.”
